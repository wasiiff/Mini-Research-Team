Relational databases (SQL) are based on tables with predefined schemas and support ACID transactions. SQL databases are ideal when you need structured data, strong consistency, and complex queries using joins. Typical examples include MySQL, PostgreSQL, and Microsoft SQL Server. They are a good fit for applications where data integrity and transactional guarantees are important — for example, banking, accounting, and inventory systems.

SQL databases scale vertically: you often add CPU, memory, or faster disks to a single database instance, or you use read replicas for scaling reads. Designing normalized schemas reduces data duplication and ensures referential integrity, but can make certain queries more complex. Schema migrations are required when changing column types or table structures, which can be challenging in production environments.

Developers benefit from mature tooling, ORMs, and a long history of best practices. SQL provides powerful query languages and indexing strategies to optimize performance. Downsides include more rigid schema management and potentially higher operational cost when scaling large write loads compared to some NoSQL alternatives.
